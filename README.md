# ППВ — карта источников наружного противопожарного водоснабжения

Приложение для пожарной части: сбор координат гидрантов и водоёмов при обходе,
поиск ближайших исправных источников на выезде, маршрут через Яндекс.Навигатор.
Работает офлайн, ставится на телефон как приложение, серверная часть не нужна.

## Размещение на GitHub Pages

1. Создать репозиторий на github.com. Имя, например, `ppv-apsheronsk`.
   Видимость — **Private**, если перечень источников относится к служебной информации.
   *Важно:* GitHub Pages для приватных репозиториев доступен только на платных планах.
   На бесплатном плане Pages работает лишь из публичного репозитория, и тогда база
   будет доступна любому по ссылке. Решение по видимости согласуйте с начальником части.
2. Загрузить в репозиторий файлы: `index.html`, `sw.js`, `manifest.json`, `icon.svg`,
   папку `data` с `sources.json`, этот `README.md`.
   Через веб-интерфейс: **Add file → Upload files** → перетащить → **Commit changes**.
3. Открыть **Settings → Pages**. В разделе *Build and deployment*:
   Source — *Deploy from a branch*, Branch — `main`, папка — `/ (root)`. Нажать **Save**.
4. Через 1–2 минуты появится адрес вида
   `https://ваш-логин.github.io/ppv-apsheronsk/`.
5. Открыть адрес на телефоне → меню браузера → **Установить приложение** /
   «На экран «Домой»». Появится значок, запуск без адресной строки.

Геолокация работает только по HTTPS. У GitHub Pages HTTPS есть по умолчанию — ничего настраивать не нужно.

## Как ведётся база

Два уровня данных:

- **Общая база части** — файл `data/sources.json` в репозитории. Одинаковая для всех устройств.
- **Локальные правки** — то, что вносит конкретный телефон. Хранятся на устройстве,
  накладываются поверх общей базы. Ничего никуда само не отправляется.

Рабочий цикл:

1. Караул при обходе вносит источники → вкладка **Учёт**.
2. В конце смены — вкладка **База** → **Выгрузить JSON**.
3. Ответственный за водоснабжение собирает файлы, объединяет и заменяет
   `data/sources.json` в репозитории (**Add file → Upload files**, тем же именем).
4. На устройствах — вкладка **База** → **Обновить общую базу**. Либо просто перезапуск приложения.
5. После того как правки ушли в общую базу, на устройстве можно нажать
   **Сбросить мои правки** — останется только общая, без дублей.

## Формат записи

```json
{
  "id": "pg-014",
  "type": "ПГ",
  "num": "14",
  "addr": "ул. Ленина, 42 — у торца дома",
  "lat": 44.462100,
  "lon": 39.730500,
  "status": "ok",
  "check": "2026-04-18",
  "net": "кольцевая",
  "dia": "150",
  "vol": "",
  "flow": "40",
  "note": "Крышка под асфальтом, ориентир — второй столб от угла.",
  "by": "ПСЧ-45, 2 караул",
  "upd": "2026-04-18"
}
```

- `type` — `ПГ`, `ПВ`, `ПИРС`, `БАШ`, `ЕСТ`
- `status` — `ok` (исправен), `hold` (ограниченно годен), `bad` (неисправен)
- `id` — любой уникальный текст. Записи с одинаковым `id` считаются одной и той же точкой,
  поэтому при слиянии файлов из разных караулов следите, чтобы номера не пересекались
  (например, каждой части свой префикс: `psch45-014`, `psch46-014`).
- `vol` заполняется для водоёмов, `dia` и `net` — для гидрантов.

## Что показывает список на выезде

Источники сортируются по расстоянию от точки отсчёта. Точка отсчёта — либо текущее
положение по GPS, либо **место вызова**, заданное нажатием на карте (кнопка «Место вызова»).
Второй режим — основной: расстояние нужно от горящего объекта, а не от машины в пути.

Расстояние считается по прямой, не по дорогам. Для выбора «какой источник ближе» этого
достаточно, но помните про реку, железную дорогу и заборы между вами и точкой —
поэтому в примечании полезно писать, откуда подъезд.

Подпись «проверка просрочена» появляется, если с даты проверки прошло больше 183 дней.

## Ограничения, о которых нужно знать

- Тайлы карты кешируются только для тех участков, которые открывали при наличии связи.
  Перед выездом в дальний куст полезно один раз прокрутить карту по маршруту дома.
- Кнопка «Навигатор» открывает Яндекс.Навигатор, если он установлен;
  запасной вариант — «Я.Карты» в браузере.
- Приложение — вспомогательный инструмент. Официальным документом остаётся
  утверждённый перечень источников водоснабжения; расхождения устраняются по нему.

## Если понадобится добрать точки из OpenStreetMap

Кнопок для этого в приложении больше нет — база собрана, раздел убран, чтобы не мешал на выезде.
Но возможность осталась: откройте overpass-turbo.eu, выполните запрос вида

```
[out:json][timeout:90];
(
  node["emergency"="fire_hydrant"](43.95,39.25,44.70,40.10);
  node["emergency"="water_tank"](43.95,39.25,44.70,40.10);
  node["emergency"="fire_water_pond"](43.95,39.25,44.70,40.10);
  node["emergency"="suction_point"](43.95,39.25,44.70,40.10);
  node["man_made"="water_tower"](43.95,39.25,44.70,40.10);
);
out center tags;
```

затем «Экспорт → данные → GeoJSON», и загрузите файл кнопкой **База → Загрузить файл**.
Приложение по-прежнему понимает GeoJSON и сырые ответы Overpass, чистит диаметры и объёмы,
отсеивает точки ближе 15 м от уже имеющихся и помечает новые статусом «не обследован».
Числа в скобках — рамка района: юг, запад, север, восток.

## Поиск на выезде

У гидрантов из OpenStreetMap нет уличных адресов — это особенность источника данных,
а не приложения. Поэтому поиск устроен наоборот: вы вводите **адрес места вызова**,
приложение находит его на карте и показывает ближайшие источники к нему.

Вкладка «Выезд» → поле адреса → «Найти» → выбрать нужный вариант из списка.
Если справочник адресов недоступен из вашей сети или адреса в нём нет —
кнопка «Указать место вызова на карте» работает всегда.

Точки без адреса подписываются осмысленно: «Пожарный гидрант Ø150 мм»,
«Пожарный водоём 50 м³», «Пожарный гидрант № 14».

## Цвета на карте и в списке

Цвет означает **состояние источника**, одинаково для гидрантов, водоёмов, пирсов и башен.
Тип виден по буквам на самой метке: ПГ, ПВ, ПИРС, БАШ.

| Цвет | Состояние |
|---|---|
| синий | исправен |
| жёлтый | не обследован |
| оранжевый | ограниченно годен |
| красный | неисправен |

Тем же жёлтым подсвечивается подпись о просроченной проверке — старше 183 дней.
